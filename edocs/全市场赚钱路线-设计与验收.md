# 全市场赚钱路线：设计、审查与验收交接

日期：2026-09-21
交付对象：后续负责实现的 Terra 任务
状态：设计方案，尚未实现；本文不构成实时收益排名。

## 1. 目标与成功标准

用户希望以自己的等级、装备、茶、房屋和 Buff 配置，快速判断全市场做什么最赚钱，包含除低级火车外的多步路线。

新增“全市场机会”入口，把分散的计算能力统一成可比较、可解释、可复现的路线榜。默认按税后期望净时薪排序，同时展示一批投入、工时、成交条件和不确定性。不能直接拼接各页面第一页结果，也不能把“每件赚最多”当成“每小时赚最多”。

完成标准：

- 同一份人物与行情快照下，单步和多步使用一致的成本、产量、工时、税费口径。
- 能比较从原料开始、购买中间品开始、加工中途出售等替代路线。
- 强化、继承、制作炼金和多步炼金进入统一比较范围。
- 低级火车使用可检查的排除规则；不得因此误排高阶装备或混合路线。
- 明确显示扫描范围和截断条件。仅扫描部分路线时，不宣称“全市场全局最优”。
- 默认不改动玩家配置、不自动交易、不发布网站。

## 4. 产品范围与默认行为

### 4.1 必须覆盖的路线族

| 路线族          | 第一版完整交付要求                                         |
| --------------- | ---------------------------------------------------------- |
| 单步            | 采集、五类生产、点金、分解、转化                           |
| 制作链          | 从各可购买中间品起步的连续升级链，含现有跨职业链           |
| 制作→炼金       | 各制作起点接点金、分解、转化；在已声明深度内继续炼金       |
| 炼金链          | 多步分解／转化／点金，分支产物分别选择出售或继续加工       |
| 强化            | 买底材强化、买已有强化等级底材继续强化，比较保护和逃逸参数 |
| 制作／继承→强化 | 现有支持的制作和继承路径，计入全部前置成本与时间           |

上述路线族按阶段交付，但不能仅完成首页聚合就宣布整个需求完成。

第一版不承诺任意循环套利、无限深度、无限强化等级、全原料任意自制组合的精确最优解。任意原料自制图扩展作为后续阶段；缺价自制若尚不支持，应标为待补价而非伪造可执行收益。

### 4.2 低级火车规则

“低级”尚无用户指定等级阈值，不擅自写死 60／100 等数字。

实现可配置规则：材料链 HRID 集合、档位截止点、仅纯材料升级链。使用配方与物品类别判断，不依赖中文名称包含关系。首次未配置时显示“低级火车排除规则未设置”，保留候选，不冒充已经排除。

规则只能排除满足定义的完整纯材料链。某条路线包含低阶材料，但最终制作装备、炼金或强化，默认保留。界面可预览命中数量及样例。规则配置完成后，才验收用户要求的排除效果。

### 4.3 榜单默认值

- 默认即时价格场景：材料按 ASK、产物按 BID；这是快照报价估算，不是保证成交。
- 挂单场景独立展示，不与即时场景混排。
- 默认计税，税率读取项目常量；硬币收入不收市场卖出税。
- 默认不排除装备、不设置 10% 利润率门槛；默认只展示正净利润，支持查看全部。
- 沿用用户当前茶和 Buff，不自动替换智慧茶、不自动开启实时 Buff。
- 含稀有掉落与不含稀有掉落可切换或并列展示。后者也不保证无随机性。
- 预算、批量／计划时长可选；未填写不能宣称“你的资金够做”。

## 5. 计算设计

### 5.1 统一边界与单位

每条路线以一批执行计划或每单位起点归一，内部统一秒、金币、物品数量；展示时转换为小时。随机步骤使用期望次数和期望产量，明确标记。

```text
净利润 = 外部出售税后收入 + 硬币收入 - 外部采购成本 - 其他步骤消耗
总工时 = Σ(每步执行次数 × 该步有效行动耗时)
净时薪 = 净利润 × 3600 / 总工时
```

其他消耗包括茶、催化剂、保护材料、金币等，不能在采购表和步骤表重复扣除。必须使用计入效率／成功率后的统一行动单位，避免 `actionsPH` 已含效率后再次乘效率。

- 内部转移只记物料，不产生买卖收入和税费。
- 每种物品区分 HRID 与强化等级；不得把 +0 和 +10 抵消。
- 外部出售中包含实际出售的副产物和剩余物；用于后续生产的部分不能再次出售。
- 上游不足需要市场补买；上游自己补产则增加相应材料与工时。
- 整批成本不等于峰值资金占用。第一版可以展示“不计中途回款的总投入估计”；只有实现执行顺序现金流后才称为峰值资金需求。
- 仓库材料不按免费处理；第一版默认从市场购买。库存模式若后续加入，应区分现金流与材料机会成本。

### 5.2 报价有效性

为采购／出售项记录价格来源、报价时间、场景、有效状态。

- 外购无报价：候选标为待补价，或展开真实自制步骤后重算。
- 无买单的产物：不能在即时榜假设卖出。允许将可选副产物明确按 0 变现计入保守估算，并列出未估值产物；主产品无变现路径不进入可执行即时榜。
- 商店固定价格仅对确实可从商店购买的物品适用，并标记来源。
- 手动报价单独标识；手动价格开关或数值变化都必须使相关结果失效。
- 缺价、失败、超时和有效但亏损分开表示，不能混为一个负利润数字。

### 5.3 路径搜索与时薪目标

不要简单修改超级炼金的节点比较为“局部时薪最大”。局部比率最大也不能保证整链时薪最大。

建议第一版采用有界枚举配合安全剪枝：

1. 枚举已声明路线族、所有合法起点、允许出售的中间节点及参数组合。
2. 炼金分支保留多个收益／耗时候选，组合后计算整链结果。
3. 只在相同输入输出边界、报价场景及约束条件下做支配剪枝；存在预算约束时同时考虑投入，避免删除低资金路线。
4. 用整链税后净利润／整链时间排序，保留最佳路径及可展开的替代路径。
5. 所有路径有稳定 ID，包含物品等级、动作、催化剂、保护／逃逸参数和供应策略。不得仅按最终物品 HRID 去重。

若实现困难，先以小规模穷举作为正确性基准，再增加剪枝。不要直接依赖旧超级炼金返回的单一节点决策。

环处理：第一版禁止重复展开当前路径已存在的状态；允许已支持且经过验证的自返期望模型。记录环截断，不宣称求解无限循环套利。路径相关的环约束不能使用仅按 HRID 的共享缓存，否则结果可能依赖遍历顺序。

最大深度、最大节点数、强化等级范围、耗时预算均为扫描参数。触发任何限制后，结果标记为“受限扫描”。“快速扫描”若只拓展 Top K，必须与“完整扫描（声明范围内）”区分。

### 5.4 成交与风险

成交量用于提示市场容量，不用于证明有足够买单／卖单深度。检查整链所有采购和出售项，包括副产物及各强化等级。

可展示计划产量与同窗口成交量的比值，但默认不假设固定市场份额，也不据此凭空计算等待时间。没有盘口深度时，不展示“保证可成交数量”。

强化保留期望次数、成功／逃逸结果与资金估计。现有 `risk` 字段是特定损耗与利润比值，不等于亏损概率；禁止换个名字显示成概率。若要显示分位数或破产概率，另行实现并验证相应分布模型。

## 7. 性能、缓存与并发

- 固定人物及游戏规则下，强化期望次数等模型结果与市场定价分层缓存；具体依赖必须通过测试确认。
- 缓存包含所有实际影响计算的输入。实时行情发生变化，即使官方时间戳没变，也应失效。
- 一次扫描使用不可变快照。旧计算器依赖全局 Pinia 时，先做适配／隔离；未隔离前禁止多个场景并发读写全局价格状态。
- 新扫描使用 generation ID；取消或配置变更后，旧任务结果不得覆盖新结果。
- 先测量，再选分块执行或 Web Worker。不能把依赖 Vue、Pinia、localStorage 的模块直接丢进 Worker。
- 页面分页和纯展示排序不触发重新枚举。预算等影响剪枝的约束变化必须重算或保留足够候选。
- 不通过静默丢候选满足性能指标；剪枝和截断数量都可查看。

性能目标为待实测目标：普通开发机上首批结果 ≤3秒、声明默认范围完整扫描 ≤30秒、取消反馈 ≤500毫秒。记录 CPU、数据规模、候选数量、冷／热缓存耗时。若未达到，提交原因和优化结果，不把部分扫描改名为完整扫描。

## 8. 实施顺序与阶段出口

### 阶段 A：确认基线

读取当前 README、构建说明及项目指导文件，检查 git 状态。保留既有未提交内容和 `gamedate/`。核对第3节事项，记录支持的路线族和参数范围，建立固定人物／行情夹具。

出口：输入导入测试、原计算器基线结果、范围清单；尚不能宣称功能完成。

### 阶段 B：统一估值核心

实现快照、物料收支、定价有效性、整链时间及缓存标识。先接单步和制作链，修复或隔离缺价回退带来的假可执行结果。

出口：单步对照、材料守恒、税费、茶耗、缺价、跨步供料测试通过。

### 阶段 C：多步与强化覆盖

接制作炼金、多分支炼金、强化与继承路线。完成候选保留与时薪选择，处理环、共享配置污染和等级范围。

出口：所有必需路线族有正向夹具；有界搜索与小图穷举对照一致。

### 阶段 D：交互与性能

完成榜单、参数、低级火车规则预览、明细、导出、取消、分批计算和性能测量。

出口：完整扫描状态可信、缓存失效正确、公开／私有边界正确。

### 阶段 E：审查与验收

执行下述审查、自动化与手工验收，修复阻塞问题后输出交接记录。不要在完成设计文档或界面壳后停止。

## 9. 代码审查流程

先审计算语义，再审搜索覆盖，再审状态／性能，最后审界面。可以由 Terra 自审或后续独立审查任务执行；本文不要求自动派生其他代理。

- [ ] 无遗漏工时、重复税费、重复茶耗、内部产物重复出售。

## 11. 构建与手工验收流程

按实际新增测试路径执行：

```bash
pnpm exec vitest run tests/opportunity
pnpm exec vitest run
pnpm build:public
pnpm build:private
```

对改动文件执行非自动修复模式 ESLint。项目 `pnpm lint` 带全仓库 `--fix`，不要为本功能顺手改写无关文件。若存在原有失败，记录基线、当前失败和影响；不能声称所有检查通过。

手工步骤：

1. 导入配套人物配置，逐项核对第2节；加载固定行情。
2. 即时价格、计税、不限制利润率、不排除装备，执行完整范围扫描。
3. 确认所有必需路线族已参与；默认范围、候选数、异常与截断可见。
4. 按配置设置低级火车排除规则，检查命中示例和混合路线保留情况。
5. 展开一个单步、一个制作链、一个制作炼金、一个分支炼金、一个强化／继承路线，按明细复算。
6. 切换挂单、稀有、人物茶配置和手动价格，验证结果及快照同步变化。
7. 扫描中取消并重新扫描，确认没有旧结果回写；验证空数据、缺价和失败提示。
8. 导出结果，与当前榜单及明细逐项核对。
9. 记录性能样本和构建边界结果。

遵守用户现有浏览器规则：只有当前消息明确授权浏览器控制时才使用浏览器工具。没有授权时完成自动化及构建检查，将浏览器交互验收标为“待用户或获授权任务执行”，不能伪称已点过页面。
